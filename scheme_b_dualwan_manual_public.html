第 1 章　方案总览与地址规划

1.1 链路结构

EasePi 网口接到承担的链路
ETH0（千兆）电信光猫 LAN（192.168.2.1）WAN_CT → 电信宽带
ETH1（千兆）移动光猫 LAN（192.168.1.1）WAN_CM → 移动宽带
ETH2（2.5G）普通交换机 LAN 口LAN 上联，全部设备从这里出去
ETH3（2.5G）调试电脑（可随时拔插）管理口 192.168.100.1
  • 两台光猫各自拨号；路由器只当 DHCP 客户端，不拨号、不桥接、不做 PPPoE。
  • 全网只有一个网段 192.168.100.0/24，交换机不参与任何逻辑划分。
  • 出口由 mwan3 决定：按连接分配，不是按设备。

1.2 地址规划

项目地址说明
LAN 网关192.168.100.1路由器 LAN 口，全设备默认网关
DHCP 池192.168.100.100 ~ .200手机、电脑、AP、其他设备自动获取
NAS（若干台）示例 .10 / .20 / .30在 NAS 系统里手工设静态，最稳；地址按实际设备顺延
摄像头示例固定段（如 .32 起）路由器 DHCP 静态租约绑定（免进摄像头后台），数量按实际填
预留固定区.50 ~ .99打印机、AP 管理地址等
WAN_CTDHCP 得 192.168.2.x电信，ETH0
WAN_CMDHCP 得 192.168.1.x移动，ETH1
⚠ 两个 WAN 必须在不同网段。若两台光猫都是 192.168.1.x，mwan3 会认错默认路由，表现为"能上网但两条线互相抢、分流乱跳"。

1.3 两种调度模式

模式成员配置表现典型场景
负载均衡跃点都 1；权重 电信2 : 移动1（或 1:1）两条线同时承载，总带宽近似叠加，按连接轮流分配设备多、经常下载/看 4K、想榨干两条带宽
主备切换主用跃点 1、备用跃点 2（本手册实机为移动优先：移动 1、电信 2）平时只走主用；探测连续失败约 15 秒切备用，主用恢复后自动切回远程访问 NAS、监控云、网游、对 IP 稳定性敏感
💡 mwan3 是按连接分配，不是按字节。所以"权重 2:1"不等于"网速正好 2:1"：多线程下载更接近，网页/聊天随机性强；同一连接（同源同目标）默认固定走一条线，避免网站登录态错乱。

易错点 TOP 5（配之前先记住）

#坑后果
1eth0/eth1 还在 br-lan 桥里WAN 建了也拿不到 IP，反而 LAN/planb 拿到光猫地址
2wan 防火墙区域只勾了一个 WAN另一条线有 IP 也用不上

第 2 章　开配前的四项准备

2.1 光猫

光猫必须满足
电信路由模式（光猫自己拨号）· LAN 网关 192.168.2.1 · LAN DHCP 开启
移动路由模式 · LAN 网关 192.168.1.1 · LAN DHCP 开启（这台改不了就保持默认）
改电信光猫的方法：电脑直连光猫 LAN 口 → 打开光猫后台 → 网络 / LAN 设置 → LAN IP 改 192.168.2.1 → 保存 → 重启光猫 → 之后用新地址进。

2.2 网线（只有 3 根核心）

网口接到作用
ETH0（千兆）电信光猫 LANWAN_CT
ETH1（千兆）移动光猫 LANWAN_CM
ETH2（2.5G）普通交换机任一 LAN 口LAN 上联
ETH3（2.5G）调试电脑（可随时拔插）管理口，192.168.100.1

2.3 交换机

普通非网管交换机即可，不做任何配置、没有后台。8 口千兆（如 TL-SG1008D，约 100 元）够用；想跑 2.5G 选 2.5G 非网管型号。
💡 摄像头若是 POE 供电，另配一台 POE 交换机或 POE 注入器，普通交换机不带供电。

2.4 一个习惯

配置全程把 ETH3 留给电脑。任何一步改错导致断网，插 ETH3 就能重新进 192.168.100.1，不用恢复出厂。

第 5 章　步骤三：把 eth0/eth1 移出 LAN 桥（最关键）

iStoreOS 出厂把几乎所有网口都桥进 br-lan，方便"即插即用"。但这样 WAN 口其实被 LAN 占着，DHCP 永远起不来 —— 这也是你之前遇到"WAN 没地址、planb 反而拿到 192.168.2.24"的根源。

1网络 → 接口 → 设备（旧版界面在 lan 卡片里点"编辑 → 物理设置"）
2找到桥设备 br-lan → "配置"
3桥端口只保留 eth2、eth3；取消勾选 eth0、eth1
4保存 → 保存并应用 → 等 20 秒
✅ 验收：回接口页，WAN_CT 出现 192.168.2.x，WAN_CM 出现 192.168.1.x，状态"已连接"。

怎么判断"真的移出来了"

检查点正确的样子错误的信号
MAC 地址WAN_CT、WAN_CM、LAN 三者 MAC 各不相同两个接口 MAC 一样（说明还共用一个桥）
接口页"设备"列WAN_CT 显示 eth0，WAN_CM 显示 eth1显示 br-lan
是否有接口拿到光猫网段只有 WAN 接口拿 2.x / 1.xLAN 或 planb 拿到 2.x（口还在桥里）
# SSH 上可以直接核实
ip -br link | grep eth        # eth0/eth1 应有 LOWER_UP
ip -br addr | grep -E "eth0|eth1|br-lan"

第 10 章　步骤八：模式 A —— 负载均衡（从主备切过来的完整步骤）

10.1 切换步骤

1网络 → MultiWAN 管理器 → 成员，分别编辑两个成员。
2均衡的前提是两个成员跃点都填 1，再用权重分配比例；主备才用跃点 1/2 分主次。按下表填：
想要的均衡比例M_CM（移动）跃点 / 权重M_CT（电信）跃点 / 权重
完全均分 1:11 / 11 / 1
移动为主 2:11 / 21 / 1
电信为主 2:11 / 11 / 2
3策略 P_MIX 同时包含两个成员；规则 r_default 指向 P_MIX（主备阶段已配好，一般不用动）。
4点 保存并应用；界面没有"重启 mwan3"按钮时，SSH 执行 mwan3 restart，等 15 秒生效。

10.2 验证是否进入均衡

#检查项通过标准
1mwan3 status 看策略两条线均 online；P_MIX 下两个成员都出现，按权重显示百分比（1:1 各 50%；2:1 约 67% / 33%），不再是某一条 100%
2出口 IP 交替连跑 5 次 curl -s https://myip.ipip.net; echo，应在移动、电信两个公网 IP / 运营商之间交替出现
3两条线流量都在走接口页 / 状态页两条 WAN 的上传、下载字节都在增长
4测速叠加多线程下载或双线程测速，总速度明显高于单条；单线程测速只占一条连接，看不出叠加属正常
💡 mwan3 按连接分配，不按字节：权重 2:1 不等于网速正好 2:1，多线程下载更接近比例，网页/聊天随机性强；同一连接（同源同目标）固定走一条线，避免网站登录态错乱。
⚠ 网银、政务、远程桌面、游戏等要求出口 IP 一致的场景，均衡下可能被风控判异常、掉登录。遇到这类设备，单独建一条规则把它固定到 P_CM 或 P_CT，或整体回退主备模式（第 11 章）。

10.3 从均衡切回主备

把主用成员跃点改 1、备用成员跃点改 2，权重都填 1，保存并重启 mwan3 即可，策略和规则不用动。具体对照见 11.1。

第 11 章　步骤九：模式 B —— 主备切换（实机：移动优先）

本手册实机为主备 · 移动优先：m_cm（移动）跃点 1 权重 1；m_ct（电信）跃点 2 权重 1。
策略、规则完全不动，保存 → 重启 mwan3。
✅ 效果：移动在线时全部走移动；移动探测连续失败约 15 秒自动切到电信；移动恢复后自动切回。要改成电信优先，按 11.1 对照表把两个跃点对调即可。

第 12 章　步骤十：WAN 默认网关与成员路由（两条都勾，靠跃点分主次）

实机验证结论：两个 WAN 都要勾选"使用该接口的网关作为默认网关"，靠网关跃点区分主次——主用跃点 1，备用跃点 2。这版 iStoreOS 下，备用线如果取消勾选默认网关，netifd 不会把网关路由下发，mwan3 对应的成员表里只有直连网段、没有 default 路由，探测包根本出不去，备用线会一直 offline。

WAN角色（移动优先）"使用默认网关"网关跃点
WAN_CM（移动）主用✅ 勾选1
WAN_CT（电信）备用✅ 勾选2
💡 主路由表会出现两条默认路由：跃点 1 的主用线优先，跃点 2 的备用线兜底；mwan3 靠 ip rule 打标记分流，优先级高于主路由表，转发流量仍按策略走，分流效果不受影响。两条都勾也保证路由器本机（NTP 对时、opkg、DDNS、应用商店）永远有路可走。
⚠ 顺序：先把 mwan3 的成员/策略/规则配好并保存应用，再确认默认网关与跃点。万一断网，插 ETH3 进后台，把对应口的默认网关勾回、跃点改回即可恢复。

15.5 IPv6 为什么 unreachable，能不能也用起来

现状原因：两条 WAN 虽然都从光猫拿到了 IPv6 前缀，但本手册的 mwan3 只配置了 IPv4 的接口、成员、策略和规则；IPv6 没有对应的 wan6 跟踪接口、v6 成员和 v6 策略，所以 mwan3 status 里 Current ipv6 policies 全部 unreachable。系统的 v6 默认路由按光猫下发走其中一条线，mwan3 不接管 v6 打标记：一条 v6 线断了，v6 流量不会自动切到另一条；客户端拿到 v6 地址后又优先走 v6，遇到不通的 v6 路径就表现为时通时断。

选择做法适用
关闭 IPv6（建议，家用）① 网络 → 接口，禁用 wan6 / WAN_CT_6 / WAN_CM_6 一类 v6 客户端接口；② 两个 WAN 高级设置取消勾选"委派 IPv6 前缀"；③ 保存应用后重启路由器没有 NAS 外网 v6 访问等硬需求，只求稳定
启用 IPv6 双 WAN① 每个 WAN 建独立 wan6 客户端接口；② 加入 mwan3 作为 v6 接口，配 v6 探测地址（运营商 v6 DNS）；③ 建 v6 成员、策略、规则；④ 防火墙区域放行 v6有 NAS 外网 v6 访问等硬需求；工作量和踩坑比 IPv4 大，mwan3 对 v6 主备的成熟度低于 v4
⚠ 在 v6 双 WAN 配通之前，不要让客户端长期挂着 v6 地址上网；建议先按上表关闭 IPv6，只用 IPv4 跑分流。
